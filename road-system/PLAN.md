# 程序化道路與街區系統 — 分階段開發計畫

> 建立：2026-09-30 ・ 狀態：第 0–5 階段完成（2026-09-30），已整合進建築專案，另外建築專案加上了燈光氛圍系統。剩下第 6 階段（未來）。實作細節見第 9 節。
> 位置：`road-system/`（獨立頁面，與建築專案共用根目錄的 node_modules）
> 讀者：實作這套系統的開發者或 AI agent。實作時只需要讀這個資料夾，不必讀建築專案的程式碼（第 5 階段整合時除外）。

## 0. 目標與範圍

**目標**
- 以模組化、程序化的方式生成道路網：路段、路口、人行道、路緣、標線、街廓地塊。
- 標線（斑馬線、停止線、車道線、中線）**由道路幾何自動推導**。調整車道數、路寬、轉角半徑、街廓尺寸、行車方向時會自動重新排列。
- 街廓內的建築先用**幾何量體**（方塊）表示。中央保留一塊「主建築地塊」，之後放入港式大樓。
- 先做成獨立頁面，完成後再整合進建築專案。

**本期不做**
- 彎路、不規則四邊形街廓：留到第 6 階段，但核心幾何從第 1 階段起就按任意角度設計。
- 車流動畫、紅綠燈號誌邏輯、坡度與高架、單行道。

## 1. 核心設計決策

這幾條決定了之後能不能不重寫就擴充到不規則街廓。實作時不要為了省事改成只支援直角的寫法。

1. **路網用「平面圖」表示，棋盤只是其中一種產生器。** 節點是路口，邊是路段，面是街廓。下游模組只讀這張圖，不知道它來自棋盤。之後做不規則四邊形時，只要換一個產生器。
2. **幾何一律用「偏移線求交 + 圓角」推導，任意角度都適用。** 不要用「直角加減半寬」這種只在棋盤上成立的算法。第 1 階段就要加一個開發用的「節點擾動」滑桿，把棋盤節點隨機偏移，驗證所有幾何在非直角下仍然正確。
3. **以街廓為中心來建構：柏油是整片地面，街廓是抬高的「島」。** 每個街廓的外輪廓就是周邊道路的路緣線（轉角做圓角），抬高到路緣高度後就是人行道。這樣不需要另外算路口多邊形或路段柏油條，也不會有接縫。
4. **標線在「路段座標系」裡生成。** 每條邊提供 `frame(s) → { 位置, 切線, 法線 }`，s 是沿路的距離。直線邊很簡單；之後換成彎路時只要替換這個函式，標線模組不用改。
5. **核心與渲染分離。** `core/` 只做純計算：可以用 three 的數學類別，但不碰 DOM 或 WebGL，輸出 `MeshData`。`render/` 才負責轉成 three.js 物件。這樣核心可以用 `npx tsx` 在 Node 裡做數值檢查，整合時也只要 import 核心。
6. **單位用公尺**，像車道 3.5 m 這類參數才直觀。整合時整組縮放：建築專案的 1 單位約等於 3 m（1 層樓）。路緣高 0.15 m 剛好等於建築專案地面的 0.05 單位。
7. **標線靠實體高度（約 1–2 cm）來避免 z-fighting，不要依賴 `polygonOffset`。** 建築專案開了 `logarithmicDepthBuffer`，shader 會自己寫入深度，`polygonOffset` 在那裡沒有效果。
8. **同一條格線上的路段必須是同一道路等級。** 這是為了避免共線路段的寬度突變（那需要漸變段），漸變段留到第 6 階段處理。
9. **地塊尺寸是輸入，道路中心線位置是推算出來的。** 格線位置 = 地塊尺寸 + 兩側人行道寬 + 兩側車道半寬。這樣調整車道數時，中央主建築地塊的大小不會變，整合時才能精準對上大樓的 footprint。

## 2. 資料模型與流程

```
參數 → 產生器(grid) → RoadGraph → 面追蹤(街廓) → 轉角 / 路口進口 → 島 / 地塊 → 各模組 → MeshData → three.js
```

```ts
interface RoadClass {             // 道路等級（橫斷面）
  id: string;                     // "main" | "minor" …
  lanesPerDir: number;            // 單向車道數
  laneWidth: number;              // m
  median: number;                 // 中央分隔寬 m（0 = 無）
  centerLine: "none" | "dashed" | "double";
  sidewalk: number;               // 人行道寬 m
  cornerRadius: number;           // 路緣轉角半徑 m
}
interface RoadNode { id: number; p: Vec2; edges: number[]; override?: { crosswalks?: boolean } } // edges 依角度逆時針排序
interface RoadEdge { id: number; a: number; b: number; cls: string | "boundary"; override?: Partial<RoadClass> }
interface Block    { id: number; nodes: number[]; edges: number[]; hero?: boolean }              // 一個面，逆時針

// 推導結果
interface Corner   { block: number; node: number; P: Vec2; t1: Vec2; t2: Vec2; arc: Vec2[] }
interface Approach { node: number; edge: number; setback: number }   // 路口口部到節點的距離
interface Island   { block: number; curb: Vec2[]; lot: Vec2[] }       // 路緣輪廓、地塊輪廓
interface MeshData { material: string; positions: Float32Array; normals: Float32Array; uvs: Float32Array; indices: Uint32Array }
```

- `boundary` 邊是地圖外框，寬度為 0。它讓最外圈的街廓也是封閉的面，一路延伸到地圖邊緣，做出參考站那種沒有邊界的城市效果。
- `override` 欄位先保留，之後做「點選個別路口或路段覆寫參數」時使用。

```

│   │   ├── layout/grid.ts  # 棋盤產生器（含開發用節點擾動）

│   └── render/             # MeshData → BufferGeometry、材質、除錯疊圖
└── tests/check.ts          # 用 npx tsx 執行的數值檢查
```

- 在根目錄 `package.json` 加上 `"dev:road": "vite road-system --port 5175"`。
- 共用根目錄的 three、lil-gui、vite、typescript，不另外安裝套件。

## 5. 分階段計畫

### 第 0 階段：專案骨架（規模小，建議 medium）
- 建立 `road-system/`、`index.html`、tsconfig 和 npm script。
- 場景：地面、半球光加平行光（含陰影）、OrbitControls、lil-gui 空骨架。
- 檢視工具：**俯視正交相機切換**（檢查標線對齊最好用）、除錯疊圖開關、線框模式。

驗收：
- [x] `npm run dev:road` 能在 5175 埠開啟，畫面正常
- [x] 俯視和透視可以切換
- [x] 根目錄建築專案的 `npx tsc --noEmit` 不受影響

### 第 1 階段：路網核心與路面（規模大，建議 max）
- `math2d.ts`：直線求交、偏移、圓角（切點、圓心、弧線取樣）、凸多邊形內縮。
- `graph.ts`：節點的邊依角度排序、half-edge 面追蹤、捨棄外部面。
- `grid.ts`：依地塊尺寸和道路斷面推算格線位置；分配主幹道與支道；加上地圖外框邊；節點擾動。
- `derive.ts`：
  - 每個街廓的路緣輪廓：偏移線求交加圓角，半徑有上限夾制。
  - 地塊輪廓：再往內縮一個人行道寬。
  - 每個路口進口的 setback。
- 模組：柏油地面、街廓島（頂面加側面，人行道鋪面的 UV 用世界座標）、路緣石頂面的亮色帶。
- 除錯疊圖：道路中心線、節點、轉角切點、setback 標記。
- `tests/check.ts` 檢查以下幾點：
  - 沒有 NaN
  - 每個街廓面積為正，且為逆時針
  - 島與島之間不重疊
  - 轉角切點都落在路段上

驗收：
- [x] 調整街廓數、地塊尺寸、車道數、人行道寬、轉角半徑時會即時重建，沒有縫隙或重疊
- [x] 主幹道和支道相交時，各自的轉角圓弧都正確
- [x] 節點擾動開到最大（非直角街廓）時仍然沒有破面，`check.ts` 全部通過
- [x] 中央主建築地塊的尺寸不受車道數影響
- [x] 5 × 5 街廓的重建時間 < 30 ms

### 第 2 階段：標線自動適應（規模中，建議 max）
- 實作路段座標系 `frame(s)`。所有標線先在路段座標裡生成，再轉成世界座標，依顏色合併成一個 mesh。
- 斑馬線：位置由 setback 推算，橫跨整個車道寬（從路緣到路緣）。紋數依寬度自動計算並置中。
- 停止線：只畫在駛入路口的那半邊，左右由行車方向決定。
- 車道分隔虛線和中線（雙黃線、單黃虛線或無）：從一端的停止線畫到另一端的停止線。
- 自動適應規則：
  - 路段太短放不下時，略過斑馬線和停止線。
  - 只在三岔以上的路口設斑馬線（可設定）。
  - 遵守個別路口的覆寫設定。
- 選配「街廓合併機率」：隨機拿掉內部路段，產生 T 字路口和較大的街廓，用來驗證斑馬線的自動適應。合併限定兩兩合併，以保持凸四邊形。

驗收：
- [x] 調整車道數、車道寬、路緣半徑、道路等級時，斑馬線的紋數和位置會自動重排，而且始終剛好在路緣到路緣之間
- [x] 切換左行和右行時，停止線會換邊
- [x] T 字路口只在三個進口有斑馬線
- [x] 節點擾動下，斑馬線仍垂直於各自的路段，且不會壓到路緣
- [x] 俯視和低角度都沒有 z-fighting

### 第 3 階段：建築量體（規模中，建議 medium）
- 地塊用雙線性四邊形參數化來切分：沿長邊依隨機面寬切段；進深太深就分成前後兩排，各自面向一條街。這個方法對矩形和凸的不規則四邊形都成立。
- 每棟量體：先內縮棟距再往上擠出，高度 = 樓層數 × 樓高。樓層數依種子隨機，越靠近中心越高。
- 顏色採參考站風格的淺灰白，每棟亮度略有差異。所有量體合併成一個 mesh。
- 主建築地塊不放量體，改放一個高亮的佔位方塊。
- 選配：裙樓（底部 1–2 層佔滿地塊，上方退縮）。

驗收：
- [x] 量體不會超出地塊，也不會壓到人行道
- [x] 調整種子、樓層範圍、面寬後會即時重建
- [x] 節點擾動下，量體仍然貼合不規則的地塊
- [x] 全城 draw call ≤ 10，三角形數 < 150k

### 第 4 階段：街道家具與質感（規模中，建議 medium，可選）
- 柏油和人行道的程序化貼圖（磨損、補丁）、人孔蓋、排水格柵。
- 沿人行道放路燈、行道樹和路樁；路口放紅綠燈桿（只有造型）；轉角放導盲磚。
- 車道箭頭（直行、左轉、右轉），依路口型態推導。
- 全部使用 InstancedMesh。

驗收：
- [x] 家具不會擋到斑馬線或路口
- [x] 效能維持在第 3 階段的預算內

### 第 5 階段：整合進建築專案（規模中，建議 medium；遇到難查的問題再切 max）

- 主建築地塊 = 大樓 footprint（length × width 單位，再乘以 3 m）。店面那一側（+z）朝向主幹道。

- 陰影範圍維持只框住主建築周邊，遠處量體不投影，避免陰影貼圖的解析度被稀釋。
- 相機、霧和燈光沿用建築專案；GUI 新增「🏙 城市街區」資料夾。
- 選配：自動降低或隱藏擋住視線的量體（類似參考站的 clear the view）。

驗收：
- [x] 大樓剛好落在主建築地塊上，店面地面和人行道同高，沒有縫隙或穿插

### 第 6 階段（未來）：不規則四邊形，之後再做彎路（規模大，建議 max）
- 新的產生器：非直角格網或自訂節點，讓街廓成為凸的不規則四邊形。
- 補齊邊界情況：
  - 共線但寬度不同的路段（漸變段）
  - 銳角路口（圓角夾限、setback 變長）
  - 非凸街廓（改用 Clipper 做多邊形偏移）
- 斑馬線方向選項：垂直於路段，或平行於路緣。
- 之後的彎路：把邊改成曲線，只要替換 `frame(s)` 和路緣偏移，標線模組不用改。

## 6. 關鍵演算法備忘

- **座標**：在俯視的 2D (x, z) 平面上計算。面一律逆時針，街廓內側在左手邊。
- **轉角**：
  - 相鄰兩條路段的路緣線（中心線往街廓內側偏移該路的車道半寬）求交，得到 P；內角為 θ。
  - 圓角切點到 P 的距離 `a = r / tan(θ/2)`；圓心在角平分線上，距離 P 為 `r / sin(θ/2)`；弧線每 10° 取一點。
  - 如果 `a` 超過該邊可用長度的 45%，就把 r 縮小到剛好符合。
- **路口 setback**：路段 e 在節點 n 有兩個轉角；取這兩個切點投影到 e 方向上的最大距離。
- **斑馬紋數**：`n = floor((跨度 + 間距) / (紋寬 + 間距))`，總寬 `n·紋寬 + (n−1)·間距`，置中排列。
- **駛入側**：座標原點設在路口，+x 沿路段離開路口，+y 為左側。靠右行駛時，駛入車道在 y > 0 那半邊；靠左行駛時在 y < 0。
- **短路段**：`可用長度 = 路段長 − 兩端 setback`。如果小於兩端各自的（離口部距離 + 斑馬線寬 + 停止線間距 + 停止線寬）總和再加 6 m，這條路段就不畫斑馬線和停止線，只畫中線。
- **地塊切分**：四邊形 ABCD 用雙線性插值 `P(u, v)` 表示。u 沿面寬邊累加隨機面寬，最後一段如果不足最小面寬，就併入前一段；v 依進深決定分成一排或兩排。

## 7. 風險與對策

| 風險 | 對策 |
|---|---|
| 為了趕進度寫成只支援直角的算法，之後要重寫 | 第 1 階段必須通過節點擾動測試才算完成 |
| 標線 z-fighting（尤其整合後的 log depth） | 標線實體抬高 1–2 cm，不依賴 polygonOffset |
| 城市一大就重建太慢，拖不動滑桿 | 核心是純計算，一次合併 mesh；超過預算時改成放開滑桿才重建 |
| 整合時尺寸對不上 | 地塊尺寸作為輸入、只用單一換算常數、第 5 階段驗收要求無縫 |
| 陰影品質下降 | 陰影只框主建築周邊，遠處量體關閉投影 |

## 9. 實作紀錄

### 第 0、1 階段（2026-09-30 完成）

**執行方式**
- 展示頁：`npm run dev:road` → http://localhost:5175/
- 數值檢查：`npm run test:road`（14 種參數變體，含 8 組節點擾動，全部通過）
- 型別檢查：`npx tsc --noEmit -p road-system`
- 頁面上的 `window.__road` 提供 `set()`、`view()`、`camera()`、`focusTop()`、`stats()`、`city()`，方便用 headless 瀏覽器驗證

**實測結果**
- 5 × 5 街廓：核心計算平均 3.4 ms（Node），瀏覽器內含建模約 6–12 ms；三角形約 1 萬；關閉除錯疊圖後共 6 個 draw call
- 主幹道從 2 車道改成 3 車道時，主建築地塊仍然剛好 21 × 9 m，中心在原點

**實作時定下的細節**（第 2 階段之後都依此為準）
- **2D 座標約定**：`world = (x, 高度, −y)`。2D 的 +y 是北方（世界 −Z）。這樣 2D 逆時針就是俯視逆時針，`left(d)` 就是駕駛人的左手邊，對靠左或靠右行駛的判斷很重要。
- **三種輪廓都由同一個函式 `offsetOutline()` 產生**，差別只在每條邊的偏移量和轉角半徑：
  - 路緣線：車道半寬，半徑取兩條路中較大的 `cornerRadius`
  - 路緣石內緣：車道半寬 + 路緣石寬，半徑 − 路緣石寬
  - 地塊線：車道半寬 + 人行道寬，半徑為 `max(0, 路緣半徑 − 兩側較寬的人行道)`。這保證地塊永遠在人行道內，轉角圓弧和路緣同心。
- **地圖外框邊寬度為 0**，轉角不做圓角；地塊在外框處內縮（路緣石寬 + 1 m）。
- **所有表面互不重疊**：路緣帶以路緣石內緣為洞、人行道以地塊為洞、主建築地塊從地塊前緣挖出缺口。共平面但不交疊，所以任何距離都不會 z-fighting。
- **setback（路口口部）** = 路段兩側切點投影到路段方向的最大值。第 2 階段的斑馬線從這裡往外放。
- **路段太短時兩端口部可能相接**（例如極端參數加上擾動）。這是合理的幾何，`check.ts` 只記為 note；第 2 階段的短路段規則要跳過這些路段。
- **細三角形**（共線點產生、面積 < 5 mm²）在建模時直接略過，避免 float32 精度把方向翻轉。

### 第 2 階段（2026-09-30 完成）

**新增的檔案**
- `core/frame.ts`：路段座標系 `edgeFrame(g, edge, fromNode)` 和 `frameQuad()`。標線全部在 (s, y) 座標裡排版：s 是從某端節點沿路的距離，y 是往左的側向距離。
- `core/markings.ts`：`planMarkings()` 把規則轉成 `MarkingPlan`（每塊標線的四邊形、每個進口的斑馬線與停止線狀態、過短路段、有斑馬線的節點）。
- `core/modules/markings.ts`：把計畫畫成白、黃兩個 mesh。

**規則**（全部由幾何推導，沒有手動擺放）
- 斑馬線：從路口口部（setback）往外 `crosswalkOffset` 開始，寬 `crosswalkWidth`；橫向跨路緣到路緣，兩側各留 0.3 m（`SIDE_MARGIN`）；紋數 = `floor((跨度 + 紋間距) / (紋寬 + 紋間距))`，置中。
- 設置條件：`override ?? (道路數 ≥ crosswalkMinRoads)`。道路數不算地圖外框邊，所以地圖邊緣的路口不會有斑馬線。
- 停止線：在斑馬線後 `stopLineGap`；只跨駛入那半邊（靠右行駛在 +y，靠左在 −y）；三岔以上的路口一定有，強制設置的直通節點斑馬線前面也有。
- 車道線與中線：從一端的停止線畫到另一端的停止線；虛線依可用長度置中排列。中線可選雙黃線、單黃虛線、無；有中央分隔（median）時改成兩側各一條黃實線。
- 短路段：如果兩端的斑馬線和停止線畫完，中間剩不到 6 m（`MIN_LANE_RUN`），這條路段就不畫斑馬線和停止線，只畫中線。
- 標線抬高 1.5 cm（`MARKING_HEIGHT`），不用 polygonOffset。展示頁也開了 `logarithmicDepthBuffer`，和建築專案一致。

**街廓合併（T 字路口）**
- `blockMerge` 機率：一般街廓隨機和東側或北側的鄰居合併，拿掉中間那段路。只允許兩兩合併，主建築街廓不參與。
- 合併後街廓的邊界上會有共線的 T 字節點（街廓不再是 4 個頂點）。第 3 階段切地塊時要先把共線頂點去掉，還原成四邊形。

**路口覆寫**
- `params.nodeOverrides` 以格線座標 `"i,j"` 為 key（節點 id 每次重建都會變，所以不能用 id）。
- 展示頁：點一下路口，就把該路口的斑馬線反轉；再點一下，恢復自動規則。被覆寫的路口在除錯疊圖上顯示綠色方框，過短路段顯示紅線。GUI 有「清除路口覆寫」按鈕。

**驗證**
- `npm run test:road`：23 種參數變體全部通過。新增的標線檢查：
  - 標線不會壓到任何街廓島
  - 所有標線兩兩不重疊（SAT 測試）
  - 斑馬紋數符合公式、左右置中、不超過路緣到路緣，而且方向沿著路段
  - 停止線都在駛入那半邊
  - 每個進口是否有斑馬線都符合規則，T 字路口剛好 3 個進口有斑馬線
  - 斑馬線在路緣位置的端點剛好落在路緣線上，也就是一定在路緣變直之後。這項用負向測試驗證過：把斑馬線往路口內縮 6 m，會報出 579 筆錯誤。
- 瀏覽器實測：靠左、靠右行駛，T 字路口，擾動加合併時偏離 18° 的路口，低角度遠景，以及真的滑鼠點擊切換覆寫。
- 效能：5 × 5 街廓含標線，核心平均 4.4–4.8 ms，瀏覽器內重建約 11 ms，約 1,900 塊標線、1.4 萬個三角形、8 個 draw call（含除錯疊圖時更多）。

### 第 3 階段（2026-09-30 完成）

**新增的檔案**
- `core/massing.ts`：`planMassing()` 產生 `MassingPlan`（每棟的 footprint、樓層、高度、亮度、裙樓與塔樓）。
- `core/modules/massing.ts`：擠出成一個 mesh（每棟的亮度用頂點色），主建築佔位量體用 `hero` 材質。
- `math2d.ts` 新增 `clipToPolygon()`（Sutherland–Hodgman）、`insetConvex()`、`dominantCorners()`、`centroid()`。

**做法**
- **四邊形與方向**：地塊先用 `dominantCorners()` 取出轉折最大的 4 個頂點，所以合併街廓邊上近乎直線的 T 字頂點會被略過。u 軸沿較長的兩邊，也就是臨街面。
- **切分**：沿 u 依隨機面寬 `[minFrontage, maxFrontage]` 切段；最後一段不足最小面寬時併入前一段。進深超過 `maxDepth` 就分成前後兩排，分隔線有少量隨機偏移。
- **每棟**：先內縮 `gap/2`，再裁切到（圓角）地塊輪廓，所以轉角大樓會跟著路緣的弧度，也不可能壓到人行道。
  - 裁切用的是「對每條邊的半平面取交集」。地塊是凸的就是一般交集；如果擾動加合併讓地塊輕微凹陷，結果是它的 kernel，只會比地塊小、不會超出。
- **主建築街廓**：在它的 (u, v) 空間分成三區：主建築左側、右側（前排），以及後方（依深度分一或兩排）。主建築地塊放佔位量體，高度 `heroFloors × floorHeight`。
- **高度**：`f = 隨機 × (1 − |bias|) + |bias| × (bias ≥ 0 ? 靠近中心度 : 1 − 靠近中心度)`，樓層 = 最少樓層 + round(f × 範圍)。最少樓層大於最多樓層時會自動對調。
- **裙樓**：6 層以上的量體依 `podiumChance` 機率變成 1–2 層裙樓，上方塔樓退縮 3 m（再裁切到裙樓內）；塔樓面積不足 40 m² 就不做。
- **隨機性以格線座標為 key**，不用每次重建都會變的街廓 id。所以調整合併等其他參數時，沒受影響的街廓會維持原樣。
- **陰影**：只有量體和主建築會投影，平面圖層不投影。展示頁的陰影貼圖改成 4096。

**驗證**
- `npm run test:road`：28 種參數變體全部通過。新增的量體檢查：
  - footprint 為凸多邊形且逆時針
  - 每棟都在自己的地塊內
  - 塔樓不超出裙樓
  - 樓層在範圍內，高度 = 樓層 × 樓高
  - 量體之間，以及和主建築之間都不重疊
  - 三角形 < 150k
- 負向測試：如果不裁切，49 個地塊共 183 個尖角會超出圓角地塊，所以這項檢查確實抓得到問題。
- 瀏覽器實測：鳥瞰、俯視主建築街廓、擾動加合併的不規則地塊、街道視角，以及用 GUI 改最多樓層後即時重建。
- **數字**：5 × 5 街廓約 320 棟、2 萬個三角形；9 × 9 約 900 棟、5.3 萬個三角形。核心平均 9 ms（Node），瀏覽器內重建 12–18 ms。
- **draw call**：城市本身 8 個 mesh。展示頁畫面總計 11 個，多出來的是展示頁的外圍地面，以及陰影貼圖的 2 次繪製。

**整合時要注意**
- 預設「往中心增高 0.3」會讓主建築周圍的量體偏高，把 6 層的主建築擋住。整合時建議改用負值（中心較低），或做第 5 階段選配的「擋住視線的量體自動降低」。

### 第 5 階段：整合進建築專案（2026-09-30 完成）

### 第 4 階段：街道家具與路面細節（2026-09-30 完成）

**路面標線與細節**（`core/markings.ts`，都由規則推導）
- **車道箭頭**：每個路口的駛入車道各一個，畫在停止線後 2 m。
  - 能轉的方向由路口實際出口的轉角決定：±35° 內算直行，35°–150° 算左轉或右轉（`exitsAt()`）。
  - 車道分配（`laneTurns()`）：路緣側車道 = 直行 + 近側轉彎（靠左行駛是左轉，靠右是右轉），中線側車道 = 直行 + 遠側轉彎；單車道則包含全部出口。T 字路口的支路沒有直行箭頭。
  - 箭頭由多塊凸多邊形組成，同一個箭頭的各塊共用 `group`。
- **人孔蓋**（12 邊形）隨機落在某條車道中央；**排水格柵**沿路緣。兩者都避開停止線與箭頭區（`DECAL_CLEAR`）。
- **導盲磚**：每條斑馬線兩端的人行道上各一片，寬度會夾在人行道範圍內，窄人行道不會伸進地塊。
- 路面貼圖加上修補塊、油漬、裂縫與骨材顆粒，12 m 無縫重複。

**街道家具**（`core/props.ts` 只產生位置，模型在 `render/props.ts`，每種零件一個 InstancedMesh）
- **路燈**：沿每條路的兩側人行道，間距 `lampSpacing`，兩側交錯排列，燈臂朝向車道；只放在停止線之外。
- **行道樹**：人行道中線，預設只種主幹道，避開路燈；人行道太窄時不種。
- **路樁**：斑馬線兩端各一對，前緣那對只放在路緣已經變直的位置。
- **紅綠燈**：每個路口進口一支，立在駛入側路緣、和停止線對齊、面向來車。每個路口是固定相位：東西向進口綠燈、南北向紅燈。
- **主建築前方淨空**：主建築地塊加上前方人行道範圍內不放家具，因為建築專案的 streetlife 在那裡種了自己的樹。
- 模型都是低面數：開口圓柱、圓片燈面、3 團樹冠。預設城市約 900 件家具，總三角形 5.5 萬；9 × 9 城市約 14.4 萬，都在 15 萬預算內。

**量體窗戶**（`render/materials.ts` 的 massing shader）
- 每面牆依「樓高 × 2.4 m」畫出窗格；白天是深色玻璃（粗糙度也較低），夜間依 `uLit` 比例隨機亮燈，有暖光和冷光。
- 窗戶發光強度（1.1）刻意低於夜間 bloom 門檻（1.2）。否則上千扇窗戶同時泛光，整個畫面會蒙上一層霧。
- 「清出視線」搬到 road-system 材質裡（`setClearView()`），展示頁也能用。量體 mesh 由 `toGroup()` 自動掛上陰影用的深度材質。
